# CLI 中文体验改进方案

实施状态（2026-09-09）：已按用户授权落实为 0.1.0-dev.2，新增 Windows 安装向导与便携打包；结果见 [本地化交付记录](../archive/localization-delivery.md)。下文保留原调研和验收范围。

2026-09-09。依据用户在 `trial/README.md` 中保留的 Windows 试用记录，以及当前 CLI 源码和已安装 Cobra v1.10.2 源码；本轮没有修改程序或替换试用制品。

## 结论与实际发现

用户的 Node/Python 示例均完整输出了“中文”参数，没有观察到乱码。当前缺少中文主要是产品文案写死为英文，尚不能据此保证所有 Windows 终端、重定向及中文输入场景均正常。

- `internal/cli/help.go`：离线手册是英文长字符串，并追加各命令帮助。
- `internal/cli/root.go`：命令说明、参数解释、状态、成功提示及错误建议主要为英文；状态直接输出 Go map，阅读体验也需要调整。
- `internal/cli/progress.go`：阶段枚举已有统一映射，是翻译进度提示的直接入口。
- `internal/cli/input.go`：交互提示及部分原因说明需要一并处理。
- `internal/core/status.go` 与其他底层错误包含英文内容，不能只替换 CLI 标签就宣称完整汉化。
- Cobra 提供 SetHelpTemplate、SetUsageTemplate、SetFlagErrorFunc；框架生成的标题、默认帮助标志与参数错误也须覆盖，不能只翻译 Short/Long。
- `internal/cli/run.go` 把子程序输出交给 runner 透传；这部分继续保持原样。

另外，试用说明误写了 `myenv status`。真实制品及当前源码仅提供裸命令状态入口，实际 `./trial/myenv.exe -C trial/node-demo` 成功输出 ready，`--help` 也没有 status。这是交付说明错误，不是用户操作问题。建议下一轮补充 status 子命令，复用裸命令的同一处理函数，并同步更正文档；保留原入口。

## 中英文边界

| 内容 | 建议 |
| --- | --- |
| help、离线手册、参数说明、交互问题 | 提供完整简体中文及英文版本，中文模式下说明文字统一中文 |
| 阶段提示、成功结果、状态及 doctor/clean 标签 | 中文模式使用中文；状态枚举转换成人能读懂的文字 |
| 常见失败原因、下一步操作 | 中文摘要与中文建议，保留稳定错误码及原始原因 |
| 命令、参数、文件名、路径、版本、URL、环境变量名 | 保留原值，如 sync、--locked、myenv.yaml、PATH |
| JSON | 键名、枚举、错误码及现有英文消息保持现有合同；路径等用户数据保持原值 |
| Node/Python/uv、用户脚本、构建工具输出 | 原样透传，不翻译、不重编码，不强制改变其语言环境 |
| completion、shell-init 生成的脚本 | 保持可执行代码语义；首轮保留现有脚本输出，中文覆盖命令自身帮助 |
| verbose 技术诊断、未分类的系统错误 | 首轮保留原始细节，外层解释可以中文 |

普通文本示例：

```text
已创建 myenv.yaml。下一步：运行 myenv sync。
正在检查环境…
正在准备 Node…
环境已就绪。

项目：C:\work\demo
配置工具：Node 22.23.2
环境状态：已就绪
下一步：运行 myenv run <command>。
```

避免每行中英双语重复；如需复现英文问题，可以显式切换。

## 实施方式与顺序

1. 第一批一起覆盖帮助、完整离线手册、正常流程提示、状态、doctor/clean、交互提示及常见错误的中文摘要/建议；修正 status 入口与说明的不一致。底层未分类错误允许作为“原始原因”显示英文，不能误译为成功或隐藏保护信息。
2. 在 CLI 层集中维护稳定消息标识和中英文本，手册内嵌于制品；不联网加载翻译，不引入外部语言包，不改变 core/runner 的执行和清理逻辑。已有错误分类继续复用，不为翻译重写租约或监督架构；不对任意英文错误做全文替换。
3. 建议提供 `--lang auto|zh-CN|en` 与 `MYENV_LANG`。优先级为显式参数、专用环境变量、系统语言、英文回退。中文系统自动选择简体中文；其他语言暂用英文。POSIX 按 LC_ALL/LC_MESSAGES/LANG 顺序识别，C/POSIX 用英文；Windows 通过本地系统语言接口识别，不启动 PowerShell 探测。此处是待实现规则，现有版本还不支持。
4. 语言必须在构造/显示帮助和处理参数错误前确定，不能只放在业务 PreRun 中。新增参数的解析遵守 run 的参数边界；例如用户命令后的 --lang 属于子程序。JSON 继续遵循上表，诊断不混入 JSON stdout。
5. 中文使用 UTF-8；先验证真实终端、重定向和管道。若旧终端存在问题，提供显式英文回退，不自动执行 chcp、不修改系统代码页或用户 Shell 配置。确有复现证据时再限定修复 myEnv 自身的输出边界。

## 定向验收

- Windows 当前 PowerShell 与原生 Kali：中文/英文帮助、完整手册、语言优先级和回退。
- 复用已安装示例运行时，核对 init/sync 的适用输出、无变更同步、裸命令/status 一致性、doctor/clean 及常见错误；不重新下载或重复全量功能回归。
- 中文参数、中文路径、交互输入、stdout/stderr 管道及重定向；确认文本可解码且内容不丢失。
- JSON 字段、枚举及消息合同不随语言变化；错误码、退出码、用户命令输出及参数转发不变。检查 --lang 不误吞子命令参数。
- help/--version 仍不联网、不初始化环境状态；翻译读取不增加文件 I/O 或外部进程。只对受改动的启动路径做必要前后核对，不重开性能调优任务。
