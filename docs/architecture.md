**myEnv：开发环境管理的共用内核与界面约定**

修订日期：2026-09-14。本文保留产品行为与可靠性约束；开发执行方式见根目录 AGENTS.md。首版为 0.1.0，GUI/TUI 共用既有 CLI 内核，性能预算仍是未全部通过的验收要求，不能把设计约定当作实测成绩。

**1. 名称采用 myEnv，命令统一为 `myenv`。** 配置为 `myenv.yaml`、`myenv.lock`，项目工作目录为 `.myenv/`。产品名保留用户指定的大小写，命令与路径使用小写，避免跨平台输入差异。

名称已有实际占用：PyPI 的 myenv 是环境变量解析库，FromDual/MyEnv 是 MySQL/MariaDB 多实例环境工具。因此不能宣称“没人用”；仍按本次决定使用 myEnv，以明确的组织仓库和发行链接区分。首版直接分发二进制；安装时检查现有同名命令，不覆盖其他工具。包注册表中的分发名在实际发布时确认，大小写不作为避让冲突的方法。[PyPI myenv](https://pypi.org/project/myenv/)、[FromDual/MyEnv](https://github.com/FromDual/MyEnv)

**2. CLI 合同保留，界面共用同一业务闭环。** 保留声明式配置、版本锁定、项目与用户默认环境分离、成熟后端复用、进程环境注入、失败恢复和结构化输出。常用操作不要求用户了解后端、存储、计划 ID 或事务参数。

| 首版交付 | 后续任务 |
| --- | --- |
| 单一 Go 可执行文件，Cobra 命令解析 | MCP、守护进程、插件市场、内嵌终端 |
| Python、Node、Temurin JDK、Go、Rust；uv 项目依赖 | 更多发行方及自动 Node 依赖同步 |
| 项目环境与当前用户默认工具链 | 主机级包、系统服务或驱动管理 |
| 配置、锁、同步、运行、诊断、一次环境回退 | 图形时间线、远程缓存、完整离线分发 |
| 简短帮助、补全、离线手册、Windows/Linux TUI | 插件市场、企业策略中心 |
| 供脚本与 Agent 使用的 JSON 输出 | MCP、HTTP 服务、多租户与远程授权 |

GUI/TUI 复用同一个核心服务；不另建 Web 服务、RPC 框架或守护进程。AI 先通过 CLI 的稳定参数、退出码和 JSON 使用 myEnv。

当前目标为 Linux x86_64/glibc 与 Windows x86_64。用户已将 macOS 排除本次交付；ARM64、musl 不在当前支持范围。Linux 容器、WSL、原生 Kali 与宿主 Windows 的验证分别记录，不混用证据。

**3. 日常记住 `init → sync → run`，改版本用 `use`，排障用 `doctor`。** 裸命令 `myenv` 只读显示项目、已配置版本、活动环境状态与必要的下一步；不启动菜单、不联网、不自动修改环境。

| 命令 | 默认行为 |
| --- | --- |
| `myenv init` | 检测现有项目文件，生成简洁配置；不安装、不覆盖已有配置 |
| `myenv sync` | 保留仍有效的锁定结果，解析缺项或变化，再准备并应用环境 |
| `myenv run python app.py` | 使用已应用环境执行命令，不隐式安装或更新 |
| `myenv use python@3.12` | 修改版本声明并调用同一同步流程；一次命令完成切换 |
| `myenv doctor` | 检查配置、实际入口与环境状态，给一条明确处理建议 |

初次使用：

```sh
myenv init
myenv sync
myenv run python app.py
```

调整版本：

```sh
myenv use python@3.12
```

`use` 明确等于“修改声明 + 同步”，不再保留只改配置却看似已经切换的歧义。若同步失败，旧环境继续保留，错误说明声明或锁是否已经更新，以及如何重试或运行旧环境。想只编辑期望状态时直接改 YAML，无需增加另一组命令。

`run` 在第一个命令参数之后停止解析 myEnv 选项，将后续内容原样作为子进程 argv；也接受 `myenv run -- python app.py`。缺少应用环境或配置已变化时提示运行 `myenv sync`，不暗中联网。首版不提供另一个任务 DSL，直接复用项目现有的 Python、npm、make 等命令。

**4. CLI 使用渐进帮助，不把低频选项摆满首页。** 参考 CLI Guidelines 的简短入口、示例与错误建议，GitHub CLI 的非交互约定，以及 Cobra 的补全机制；具体行为按下表固定。[CLI Guidelines](https://clig.dev/#help)、[GitHub CLI 环境变量](https://cli.github.com/manual/gh_help_environment)、[Cobra 补全](https://cobra.dev/docs/how-to-guides/shell-completion/)

| 入口 | 展示内容 |
| --- | --- |
| `myenv` | 不超过一屏的当前状态；无项目时显示入门示例 |
| `myenv --help` | 三步工作流、use/doctor、手册入口 |
| `myenv sync --help` | 本命令用途、常用选项、两个示例 |
| `myenv help sync` | 完整语义、全部参数、失败与退出行为 |
| `myenv help manual` | 完整离线手册；非 TTY 输出普通文本 |
| `myenv completion <shell>` | Bash/Zsh/Fish/PowerShell 补全脚本 |

帮助、手册、参数表和补全从同一命令定义生成，随二进制版本发布；帮助不访问网络、不启动后端、不初始化安装状态。补全仅查本地配置与缓存，不能每按一次 Tab 就查询远端版本。手册输出可在 TTY 使用已有 pager，缺少 pager 时直接打印。

只有 TTY 中确实缺少必要信息时才提问，例如检测到互相矛盾的版本文件。CI、管道、`--json` 或 `--no-input` 下不等待输入，返回 `NEEDS_INPUT` 与补齐方法。常规受管安装无需反复加 `--yes`；需要构建代码时，一个 sync/use 调用最多确认一次，也可用 `--allow-build` 事先明确授权本次工作区解析与安装所需构建。首版不建设持久授权缓存；Shell 配置由用户按手册一次性设置，不自动修改。

成功输出保持简短：结果、变化、必要下一步。错误输出包含错误码、原因与一条建议，默认不打印堆栈；`--verbose` 才给诊断细节。长安装显示当前阶段，不输出高频动画或逐文件刷屏。TTY 可着色，管道和 `NO_COLOR` 使用纯文本。

**5. 配置只保留用户真正需要填写的字段。** 初版默认后端由程序选择，不要求用户写 provider、engine、capabilities、策略版本或 API 对象类型。

```yaml
schema: 1

tools:
  python: "3.12"
  node: "22"

python:
  project: "."
  groups: [dev]

env:
  APP_ENV: development
```

版本仅为结构示例。`tools` 为必需内容；其余字段按需填写。不管理 Python 依赖时省略 `python`。存在 `pyproject.toml` 时 `init` 可生成 `python.project`；只有项目确实定义了 dev 组才生成对应 groups。

Python 依赖仍以 `pyproject.toml` 和 `uv.lock` 为真源，不复制一份 packages 清单到 myEnv 配置。Node 的 `sync` 只管理运行时，不隐式安装项目包；依赖通过项目原管理器或 GUI 包管理显式操作，继续保存原生声明和锁。配置中的环境变量只允许普通字符串；密钥由调用进程按需传入，不写入配置、锁或日志。

`init` 检测 `.python-version`、`pyproject.toml`、`.node-version`、`.nvmrc` 与 `package.json` 的声明，不猜测缺失依赖、不执行仓库文件。有冲突时展示来源；无可用版本信息时，TTY 允许选择，非交互模式给出需要补充的字段。已有 myEnv 配置时直接返回现状，不覆盖。

YAML 校验拒绝重复键、未知字段、危险 tag 与越界路径，并限制文件大小和展开深度。默认每个工作区只有一份生效配置，不做隐式多层合并；monorepo 可通过指定项目目录或 Python 项目路径使用，复杂继承后置。

用户默认环境使用用户配置目录中的独立 `profile.yaml`，内容同样采用 `schema` 和 `tools`。`--global` 只表示当前用户默认值，不能提权或修改系统包。项目版本优先且默认不继承用户版本，避免机器差异污染项目结果。

**6. `sync` 合并操作步骤，内部继续区分解析与安装。** 用户不再需要依次记住 lock、plan、apply。

| 输入状态 | `sync` 行为 |
| --- | --- |
| 无环境锁 | 解析当前平台所需版本，生成锁，再安装 |
| 声明与锁一致，环境健康 | 直接返回，无网络、无新环境代 |
| 声明改变 | 仅重新解析受影响项，保留仍满足要求的其他锁定项 |
| Python manifest 改变或缺 uv.lock | 委托 uv 更新依赖锁，再记录摘要和同步 |
| 已锁版本仍满足范围 | 不因为远端发布新版而自动升级 |
| `--locked` | 要求所有相关声明与锁一致；缺锁或过期即失败，不改锁 |
| `--update python` | 显式刷新 Python runtime 的锁定解析，其他项尽量保留 |
| `--dry-run` | 展示拟议变化，不改声明、锁或环境；必要元数据解析可联网，不能执行构建 |

若解析依赖必须执行动态构建元数据，dry-run 只报告该需求。预览是信息，不是执行凭证；真正 sync 使用当前输入重新规划，不能把先前预览当成无条件授权。

`myenv.lock` 使用 JSON，记录 schema、配置摘要、平台、精确版本、固定后端身份、可获取的制品 URL/摘要、Python 原生输入摘要及安装选项。只为实际支持的目标保存解析；当前平台缺项时普通 sync 显式补充，`--locked` 拒绝补充。首次安装可以解析，已锁定后不隐式升级后端。

首版准确区分 `version` 和 `artifact` 两级锁定证据，不建设通用能力框架：能强制获取预先锁定字节的资源标 artifact；只能固定版本与安装记录的资源标 version。锁文件和诊断如实展示，不能拿安装后的目录哈希充当下载前制品锁。uv 的同一 Python 版本可能对应更新的发行构建，因此初版不笼统承诺所有 Python 重装逐位相同。[uv 安装 Python](https://docs.astral.sh/uv/guides/install-python/)

锁文件可能先于安装完成写入。失败时它表达下一次重试的期望，活动环境仍引用旧代；结果明确两者的差异。myEnv 不宣称文件、后端安装与数据库一起跨资源原子提交。

**7. 内部保持六个明确模块，不引入通用插件或工作流平台。** 采用 Go + Cobra、标准库优先、一个 YAML 库和一个经过目标平台验证的 SQLite 驱动。只在需要替换实现的后端与平台边界定义小接口，不给每个类套抽象层。

| 模块 | 内容 |
| --- | --- |
| `cli` | 命令、帮助、补全、TTY 与输出 |
| `config` | 配置、工作区发现、锁与小输入摘要 |
| `core` | use/sync/inspect/rollback 的应用流程与内部 diff |
| `backend` | 固定 uv、Python 官网 ZIP、Node/Temurin/Go/Rust 发布包 |
| `state` | 对象、环境代、活动引用、操作恢复与清理 |
| `runner` | 子进程环境、参数、信号和平台 launcher |

core 接受普通请求结构并返回普通结果结构，不直接写终端。GUI/TUI 通过共享用例调用这层，不实现网络协议。

后端只需“解析、准备、验证”三个窄操作，解释器与依赖同步分开。同一资源只归一个所有者管理：uv 管理其解释器目录，myEnv 不移动该目录；myEnv 管理 Node 对象、官网下载的 SDK 与自己的 venv 代。清理时先检查引用，再通过对应所有者释放。

myEnv 本身和固定辅助引擎以受控发布包安装，使用可信摘要和可用签名；默认官方源，可显式配置镜像。首版不做自动测速、源码编译回退或自动修改 TLS 校验。代理、CA 和镜像配置遵循已支持后端的明确设置，避免重复实现完整网络栈。

**8. 环境发布保留必要的可靠性，缩小到受管范围。** 不做全 store 压缩快照、不要求常驻进程、不运行后台 GC。

| 数据 | 位置与用途 |
| --- | --- |
| 项目声明与锁 | `myenv.yaml`、`myenv.lock`，提交 Git |
| 项目环境代 | `.myenv/generations/<id>/`，不提交 Git |
| 共享运行时与缓存 | 平台用户数据/缓存目录，不写系统目录 |
| 用户默认配置 | 平台用户配置目录中的 myenv/profile.yaml |
| 小型状态库 | 活动引用、对象归属、最近操作、进程租约 |

同步顺序固定：读取并记录输入 → 获取工作区修改锁 → 准备新代 → 验证 → 复核输入与状态 → 提交活动引用。不同项目可以并行，共享下载按制品去重；同一项目修改串行。首版使用固定步骤与少量并发，不实现通用 DAG 调度器。

新 venv 在最终唯一目录创建，成功后只更新数据库引用。状态库是活动代的唯一事实源；文件完成并按平台要求落盘后，再在一个短事务中切换引用并记操作结果。Go 非 Unix 平台的 rename 不能当作统一原子替换保证，采用同一数据库引用路径减少分支。[Go os.Rename](https://pkg.go.dev/os#Rename)、[SQLite Atomic Commit](https://sqlite.org/atomiccommit.html)

准备失败保留旧代，退出时返回失败阶段与重试命令。崩溃后根据已登记 operation 和完成标记恢复，不能删除另一进程正在创建的目录。提交前输入变化返回 `INPUT_CHANGED`；每个代保存实际使用的输入摘要，外部编辑器的后续修改由状态检查识别。

`rollback` 默认切回上一个保留代，不改项目代码和锁文件。活动代与现声明不同时，普通 run 提示 sync；`run --current` 显式运行当前已经应用的代，允许它与现声明不同，但仍检查环境完整性和权限。同步失败时它运行保留下来的旧代，rollback 后它运行回退目标。首次安装没有可用活动代时给出直接错误。回退和失败恢复不覆盖数据库内容、npm 安装副作用、主机配置或用户直接改坏的目录。

`run` 在选代的同一短事务中登记租约。Linux 保留独立监督器：主进程 SIGKILL 后仍负责后代回收与完成回执，SIGSTOP 期间仍执行截止时间；现有合并实验不等价，不重新默认尝试删进程。Windows 使用单个 myEnv 进程和创建时关联的 Job Objects。清理重新检查引用并标记 deleting，随后才删除；不得仅因心跳过期就假定子进程结束。首版只提供手动 `clean`，保留活动代、前一代、运行中代和未完成操作；不自动删除长时间未使用的项目。

缓存流式写入和校验，解包检查越界路径、链接与大小限制。共享可写文件默认复制或 CoW，不把项目 venv 与可信缓存硬链接成同一可改写文件。缓存清理不能破坏活动环境。

**9. Python 与 Node 的首版行为具体限定。** Python 解释器优先通过锁定版本的 uv 安装到专用受管目录，由 uv 完成平台路径修补；安装来源与构建信息能验证多少就记录多少。首版先兑现版本选择与失败恢复，强制构建制品绑定独立验证后再启用，不为获得这一额外保证重写 Python 安装器。

创建与同步 Python 环境的基础调用：

```text
uv venv --python <absolute-python> --no-python-downloads <final-generation>/venv
uv sync --locked --python <absolute-python> --no-python-downloads
```

第二条通过 env map 指定 `UV_PROJECT_ENVIRONMENT=<final-generation>/venv`，cwd 固定到配置中的 Python 项目。依赖锁需要更新时先执行相应 uv 锁定流程。`--locked` 与 `--frozen` 语义不同；此处使用前者检查输入一致性。直接执行已选环境避免 `uv run` 自动同步带来的隐式工作。[uv 项目配置](https://docs.astral.sh/uv/concepts/projects/config/)、[uv Locking and syncing](https://docs.astral.sh/uv/concepts/projects/sync/)

上述仅为基础参数，实际还需传入组选项及本次构建策略。安装 Python 依赖或 editable 项目可能执行代码；默认优先已有 wheel，需要构建而未获准时，TTY 在本次调用中说明并确认一次，自动化返回错误并提示 `--allow-build`。已明确授权的本次操作不逐个包反复询问；无变更 sync 不启动构建。该参数允许构建代码以当前用户权限执行，不构成沙箱。不把 `--no-build` 当成完整隔离，因为 uv 仍可能构建第一方 workspace 包。[uv 环境变量](https://docs.astral.sh/uv/reference/environment/)

venv 不在构建完成后搬迁，项目路径变化后重建。IDE 可通过 `myenv doctor` 获得实际解释器路径，首版不自动重写 IDE 文件，也不把 `.venv` 符号链接设为运行必需条件。[Python venv](https://docs.python.org/3/library/venv.html)

Node runtime 使用固定官方制品；与所选发布包配套的 npm 一起记录。首版可运行 `myenv run npm ci`，其 node_modules 变化属于用户启动的项目命令，不纳入 myEnv 环境回滚。普通 run 是代码执行入口，不是安全沙箱；PATH 隔离不限制文件或网络权限。[npm ci](https://docs.npmjs.com/cli/v12/commands/npm-ci/)

**10. 响应速度与内存占用作为首版验收项。** 以下是工程预算，不是已取得的成绩；基准在固定发布构建、受支持本地 SSD、记录的参考硬件上测量，不计用户命令的执行耗时。

| 场景 | 延迟预算 | myEnv 自身峰值 RSS |
| --- | --- | --- |
| `--help` / `--version`，热文件缓存 | p95 ≤ 30 ms | ≤ 32 MiB |
| 裸命令状态 / run 附加开销，热缓存 | p95 ≤ 50 ms | ≤ 32 MiB |
| 无变更 sync，小型 Python+Node 项目 | p95 ≤ 200 ms | ≤ 64 MiB |
| 下载与准备环境 | 前台 ≤ 100 ms 显示当前阶段；网络耗时单报 | ≤ 64 MiB，不含 uv 或其他子进程 |
| 命令结束后的后台占用 | 无常驻进程 | 0 |

冷缓存启动单独记录，不拿热缓存数字代表冷启动。run 开销以同一平台直接运行相同可执行文件为基线，包含项目检查、活动引用读取和租约登记。端到端内存另报 myEnv 与整个子进程树的峰值；限制父进程内存不等于限制 uv、编译器或用户程序的内存。某平台达不到预算时先定位瓶颈，再明确调整目标，不省略数据。

实现约束：

- 帮助和版本走独立快速路径；不打开状态库、不扫描 PATH 或启动 uv。
- 状态只读当前 profile 与小型输入文件；run 另外读取活动引用并登记租约。两者都不遍历 store、不计算全目录哈希、不联网检查更新。
- 无变更 sync 使用输入摘要和安装记录快速返回；只核对必要入口存在性，深度内容检查放到 doctor。
- 大制品使用固定缓冲流式下载、解包、校验；初始下载并发为 2，同一环境物化串行。
- 子进程输出默认直通；失败摘要使用有界环形缓冲，例如 256 KiB，完整日志按需写磁盘并设上限。
- 补全只查本地；按需加载后端；取消无用途的轮询、启动更新检查和后台索引。
- 优先减少 I/O、子进程和重复工作，只有基准证明必要时才做对象池、手写解析或其他复杂优化。

快速状态检查不能发现版本号未变的所有手工篡改，`doctor --deep` 才核对受管内容证据；输出明确检查级别。为速度放弃每次全量扫描，不等于声称每次 run 完成了完整校验。

**11. 开发按变更范围验证，禁止无信息增量的重复测试。** 先实现一个完整纵向流程，再扩展平台与工具；每个阶段只新增为当前风险服务的代码和测试。

| 变更类型 | 需要运行的验证 |
| --- | --- |
| 文案、帮助、方案文档 | 内容与示例检查；不启动真实安装、不跑端到端套件 |
| 配置/参数解析 | 受影响模块测试与已有样例 |
| 同步/存储/恢复 | 对应模块测试，加一个相关集成场景 |
| argv/信号/平台入口 | 对应目标平台的进程测试 |
| 启动、状态或下载性能路径 | 一次固定基准批次，记录延迟和内存 |
| 合并/发布候选 | 一次集中验证已支持平台的完整核心流程 |

以“代码内容/提交 + 后端版本 + OS/架构 + 测试配置”标识结果。同一组合通过后复用结果；不因换一个命令包装、担心不够充分或换个执行者而重复全量跑。本地与 CI 职责互补，固定集成制品可缓存，不反复清空后重装。

只有代码或依赖变更、目标平台变化、已发现失败、明确环境异常时才补测。失败先定位、修复，再跑失败用例与确有影响的关联范围；禁止无诊断的连续重跑。网络异常最多进行一次有记录的确认，不用重试掩盖产品错误。

性能基准的固定样本数量属于一次必要测量，用于得到 p95；这与无变更重复整个测试流程不同。仅性能相关修改或发布门禁运行基准，不在每次文案修改后测启动速度。

首版保留的核心验证场景只有七组，每组覆盖不同风险：

1. 配置发现、冲突与非交互缺参不挂起。
2. 首次 sync 成功，紧接一次重复 sync 无下载和代际变化。
3. 校验、安装或提交前失败时旧环境可用。
4. run 的参数、stdio、退出码和取消信号正确。
5. 全局与项目隔离，修改一边不改变另一边。
6. 同项目并发同步、崩溃恢复、运行中对象不被清理。
7. 所支持平台的发布包与性能预算验证。

其中“连续 sync 两次”是验证幂等性的一个必要测试，不是反复测试要求的例外扩张。测试通过并解决具体风险后，继续开发，不添加仅重复实现逻辑的测试。

**12. 使用手册收纳低频命令和全部参数。** 以下是首版手册内容基线，同时用于生成离线帮助；首页只显示核心工作流，不要求用户记忆本表。

| 命令/选项 | 手册中的完整约定 |
| --- | --- |
| `init` | 在当前目录检测并生成配置；不安装；已有配置不覆盖 |
| `use <tool>@<version>` | 编辑声明并同步；支持 python/node/java/go/rust；失败说明配置与活动代状态 |
| `use` 无参数 | TTY 可选工具与版本；非 TTY 返回用法，不猜测 |
| `sync` | 按第 6 节更新必要锁并应用，保留有效现有解析 |
| `sync --locked` | 不修改 myenv.lock 或原生锁；不一致即失败；推荐 CI 使用 |
| `sync --dry-run` | 预览变化；无安装、锁写入或构建；与 `--locked` 可组合 |
| `sync --update <tool>` | 刷新指定 runtime 解析；与 `--locked` 互斥 |
| `--allow-build` | 仅用于 sync/use，明确允许本次工作区依赖解析、安装和项目安装所需构建代码；不授权主机管理；dry-run 仍不执行构建 |
| `run [--] <command> [args...]` | 直通参数与 I/O；不安装；返回子进程退出状态 |
| `run --current <command> [args...]` | 显式使用当前已应用代，允许它与声明不同；不跳过环境/权限检查；选项必须位于 command 前 |
| `run --global <command> [args...]` | 使用用户默认工具环境，不读取项目工具版本 |
| `doctor` | 检查配置、锁、入口、PATH 遮蔽与已知漂移，输出一个建议动作 |
| `doctor --deep` | 额外检查受管文件证据；可能较慢；不会自动修复 |
| `rollback` | 切回前一代，保留现有声明/锁，明确提示不一致 |
| `clean` | 手动清理无引用缓存与旧代；保护当前/前一代/运行中/未完成对象 |
| `clean --dry-run` | 列出实际可清理项和预估大小，不删除 |
| `--global` | 仅用于 use/sync/run/doctor/rollback；作用于用户 profile；不表示 OS 管理 |
| `-C <path>` | 显式指定项目上下文，避免长路径和重复切目录 |
| `--json` | 用于状态、init/use/sync/doctor/rollback/clean、versions 与 system 管理命令；输出一个 JSON 结果，关闭交互 |
| `--no-input` | 关闭交互；缺少必要信息/授权就失败；不自动同意任何权限 |
| `--verbose` | 诊断日志输出到 stderr，不改变 JSON 结构 |
| `-h` / `--help` / `--version` | 离线、只读、快速返回 |
| `help <command>` / `help manual` | 完整参数、示例、错误处理和手册 |
| `completion <shell>` | 生成补全脚本，安装方式在手册中按平台说明 |

保留已实现的 status 和 list 快捷入口，不扩张命令缩写或同义别名；`run` 不提供 JSON 输出捕获。未知命令可给拼写建议，不自动执行猜测结果。未支持的参数组合在任何修改前拒绝。

CI 示例：

```sh
myenv sync --locked --no-input --json
myenv run python -m pytest
```

可信项目确实需要源码或 editable 构建时，在 sync 命令加 `--allow-build`；其含义为本次代码执行许可，和 `--locked` 的锁一致性要求独立。对未知仓库不要把该选项设为通用默认值。

JSON 结果固定为 `schema`、`ok`、`changed`、`data`、`error`；失败 error 包含 `code`、`message`、`next_action`，不返回待执行 Shell 字符串。stdout 只放最终 JSON；进度和诊断去 stderr。对 CI 提供稳定错误码：`INVALID_CONFIG`、`NEEDS_INPUT`、`LOCK_OUT_OF_DATE`、`INPUT_CHANGED`、`DOWNLOAD_FAILED`、`CHECKSUM_MISMATCH`、`SYNC_FAILED`、`ENV_NOT_READY`。

退出码：0 成功；1 执行/环境错误；2 用法或配置错误；3 需要输入或授权。run 启动后透传子进程退出码，启动前失败使用 myEnv 退出码；进程被信号终止按平台约定处理，并在手册解释。

手册另外包括四个短专题：首次安装与卸载、用户默认环境与 PATH、代理/镜像/凭证、失败恢复与磁盘清理。支持项目目录向上查找但不越过明确工作区/VCS边界；用户默认工具通过一次显式 Shell 集成启用，首版项目自动切换以 myenv run 为准。卸载自身与删除环境分开，避免顺手删除用户项目。

| 将来 GUI 造成两套逻辑 | GUI/TUI 复用 core、来源查询和运行用例，仅保留进程内有界任务接口 |

## 界面合同

- Windows Wails v2.14.0 + React 19.2.6/TypeScript 5.9.3/Vite 8.2.2；GUI 使用独立静态资源、独立入口和 `windows && gui` 构建标签。普通 CLI 不依赖 Wails/WebView2。
- Windows/Linux Bubble Tea v2.0.9，显式 `tui`，裸命令仍为状态。退出 Tea Program 并等待事件转发退出后，同进程执行共享 `RunCommand`，保持 SelectRun → runner.Execute → Finish；使用根命令 context，绝不复用已取消的 Tea 子 context。Tea/Cobra/runner 信号处理不重叠。命令完成后重建 Tea；最大刷新率10 Hz。
- Linux 保留独立监督器、持久租约与完成回执；终端子进程组只在 leader 尚未回收时参与信号转发，同组直接子进程不重复转发。Windows 后台进程增加 CREATE_NO_WINDOW，不替换挂起创建、Job 关联或句柄白名单。
- GUI 外部运行核验同目录 CLI 的版本，使用绝对应用路径与逐个转义的 Windows 参数，通过 CREATE_NEW_CONSOLE 创建真正的控制台标准句柄，不经 shell 字符串拼接解释。只报告交接；GUI 关闭不取消已交接命令。
- 任务请求为值快照，固定目录/作用域/镜像/CA；串行任务，最多16个结果，外部管理器日志最多64 KiB。事件按任务 ID 合并，最终结果保留并可查询；不丢错误来换流畅度。原管理器需要额外交互时，转 CLI 处理，不模拟输入许可。
- 构建许可只进入指定当前任务；取消等待核心收尾。OnBeforeClose 阻止首次关闭，异步取消并等待任务完成后调用 Quit；不依赖页面销毁后的确认框。
- GUI/TUI 不复制解析或安装目录。Python 官网发布页与固定 uv 的 Astral 可安装目录分开，发布页不能点击安装；查询缺少 uv 时明确报错，不为查询隐式安装。
- 工作台对选定目录只读：没有本目录声明时显示空状态，不向父目录隐式执行操作。完整规范化路径标识项目，用户默认草稿独立；切换不得改变任务快照。UI保存期望只预览，确认同步通过ExpectedDigest防止声明变更后应用旧预览，CLI use仍编辑并同步。

- UI操作请求按动作限定选项，预览不能串入修复/升级。GUI交接的CLI仅在Run/Finish完成后保留终端结果到Enter，不延长租约，不改变普通CLI的返回与参数透传。TUI运行确认页不增加进程，仍完整退出Tea再交接。

- 界面选择版本仅改草稿；明确保存声明（空项目先确认本目录初始化）后预览整个目标环境，再确认同步。GUI 顶栏/任务状态固定，版本主操作与预览确认可达；变更、只读历史、按需日志使用中央区域，历史不得携带其他任务的执行按钮。新任务使旧预览失效；TUI 按环境与语言组织，维护操作为次级入口，Enter只作用于当前焦点。同步重建标志只属于当前同步请求，不串入其他动作。
- Windows新解压SDK目录临时重命名被占用时，仅对访问/共享错误最多重试2秒，等待可取消；不改权限、不覆盖活动环境，不降低刷盘或发布保护。

- Windows TUI只在页面/编辑边界通过Tea清屏命令使旧页失效，避免原生控制台残留；不引入空闲重绘、不影响同进程终端交接。

- 外部管理的界面执行绑定已保留的成功核验任务 ID 和完整请求快照；Go 侧读取原计划，执行前重新核验并比较，目标/管理器/动作变化必须重新确认。GUI 历史只读，重新进入计划不自动扫描替换它。TUI 对完成任务按 ID 去重，后台完成不打断编辑或历史查看。

- GUI“本机环境”显示应用继承的 PATH 命令、完整路径与检查时间，不能等同于每个终端或 OS 全局安装；既有 `--global` profile 在 GUI 中称为“myEnv 默认工具链”，合同保持不变。首次检查由用户启动，可附加明确选择的项目目录，可跳过；确认后只保存有时间标记的检查记录，不写 PATH、不接管外部安装。项目记录与本机记录分开，后续刷新入口可见。
- 本机探测统一经过 runner 后台执行，不闪控制台；进程、时间、目录数量、输出有界。Node 项目声明/直接安装元数据与已识别全局根分开，npm/pnpm 调度器不为检查执行。Python 包绑定明确解释器，以隔离模式读取元数据，不执行 site hooks、不将本机解释器推断为项目环境。包检查保持只读；明确进入包管理后按下一条规则操作。Node 压缩包缓存共享，跨项目解压池须连同引用、租约、完整性与清理机制单独实现。
- Java 查询展示常见版本名、上游 LTS 元数据与精确发布 ID；`1.8`/`jdk1.8` 等仅按 Java 语义归一化。默认展示各主版本近期稳定发布，预览明确标记；配置语法不支持的上游 ID 仅作为只读发布记录。安装解析仍保留历史精确版本能力，近期列表不是完整归档承诺。
- TUI 仅在显式运行确认时设置并单次消费终端交接标记；Tea 正常结束或收到退出信号本身不构成运行授权，不得执行默认命令或重开界面。窗口图标是 GUI 专用 Windows PE 资源，普通 CLI 不包含这些资源。

- GUI 包管理按单一项目、全局包位置或 Python 解释器生成计划；官方 npm/PyPI 元数据与安装管理器分离。执行仅接受保留的成功计划 ID 和相同请求，单次消费、执行前核验状态；latest 在预览解析为精确版本。Node 项目保存原生声明与生效锁中的期望，锁仍保留本次精确版本；外部 Python/全局 latest 仅为本次目标，不自动后台升级。
- 包操作使用原 npm/pnpm/pip 或可核验官方收据的 uv；未知所有者、工作区复杂布局和 myEnv 活动 Python 代不直接改写。安装脚本默认禁用，Python 仅 wheel；外部包变更不承诺原子回退，失败/取消重新核验并逐项报告。管理器自身必须单独处理；uv 独立安装没有卸载 API，交回原安装方式。界面显示这些能力边界，不把只读核验冒充真实升级验证。
